> วางไฟล์นี้ให้ AI ทั้งไฟล์ แล้วให้ AI อ่านไฟล์ในโปรเจกต์ที่ระบุไว้ในหัวข้อ 9 เพื่อยืนยันตัวเลขก่อนใช้
> ภาษาของสไลด์: ไทย (ศัพท์เทคนิคเป็นอังกฤษได้) ผลลัพธ์สุดท้ายต้องส่งเป็น **PDF เท่านั้น**

## 1. บทบาทและเป้าหมาย

คุณคือผู้ช่วยทำ **สไลด์สำหรับพรีเซนต์บนเวที** ของโปรเจกต์กลุ่มรายวิชา Intelligent System Development (สจล.) เรื่องระบบ **OCR Transcript**:
อ่านใบแสดงผลการเรียน (PDF หรือภาพถ่าย) แล้วแปลงเป็นข้อมูลโครงสร้าง (JSON) ตรวจสอบ แก้ไข บันทึกลงฐานข้อมูล และค้นหาผลการเรียนได้

**เงื่อนไขการพรีเซนต์ (จากอาจารย์):**
- กลุ่มละ **10 นาที** + ตอบคำถาม **3 นาที**
- **ไม่มีรายงานแยก** — สไลด์คือสิ่งเดียวที่ส่ง (ส่งเป็นไฟล์ **PDF**) อาจารย์จะเปิดอ่านเองทีหลังอย่างละเอียด
- โครงที่อาจารย์กำหนด:
  1. บอก **application** (ชื่อกลุ่ม + รหัสนักศึกษา) **ไม่เกิน 1 นาที**
  2. **เน้น process, model, algorithm, parameters** (ส่วนที่ใช้เวลาพูดมากที่สุด)
  3. **สรุปผล** ที่มี evaluation metrics และระยะเวลาที่ใช้ **1–2 นาที**

**ดังนั้นสไลด์ต้องทำสองหน้าที่พร้อมกัน:**
- **ตอนพูด:** ผู้ฟังอ่านได้ในไม่กี่วินาที ผู้พูดเล่าตามได้ทัน 1 สไลด์ใช้เวลาราว 40–60 วินาที
- **ตอนอาจารย์อ่านทีหลัง:** ต้องเข้าใจได้โดยไม่มีคนพูดประกอบ — ชื่อสไลด์เป็นประโยคสรุปใจความ มีคำอธิบายสั้นๆ และที่มาของตัวเลข ส่วนรายละเอียดเต็มอยู่ใน **สไลด์สำรอง (Backup)** ท้ายไฟล์ (ข้อความใน speaker notes จะไม่อยู่ในไฟล์ PDF จึงห้ามพึ่ง notes)

## 3. กฎความซื่อสัตย์ของตัวเลข (สำคัญที่สุด)

อาจารย์จะตรวจละเอียด ผิดพลาดเรื่องตัวเลขเสียหายกว่าตัวเลขที่ต่ำ

1. **ห้ามแต่งตัวเลข** ทุกตัวเลขต้องมาจากหัวข้อ 6–7 ในไฟล์นี้ หรือจากไฟล์ที่ระบุในหัวข้อ 9 ถ้าไม่มีให้เขียนว่า "ต้องวัดเพิ่ม" แล้วบอกในรายงานท้ายงาน
2. **แยกชนิดอินพุตเสมอ**: PDF ดิจิทัล / ภาพต้นฉบับ (PNG เรนเดอร์จาก PDF) / ภาพมี noise / ภาพ augmented (หมุน เบลอ มืด perspective) / ภาพถ่ายกล้องมือถือ / ภาพถ่ายหน้าจอ ห้ามเอาผลของ PDF ไปอ้างเป็นผลของภาพ
3. **แยก blind test กับ reused test**: ผลทดสอบครั้งแรกบน test set คือ blind แต่หลังนำ error มาปรับระบบแล้วต้องเรียกว่า "reused test" ห้ามเรียกว่า blind
4. **ห้ามรวมผลคนละชุดเป็นคะแนนความแม่นยำเดียว** (เช่น เฉลี่ย 97% และ 70% แล้วบอก 85%)
5. รายงานแต่ละกลุ่มมาจากโค้ดคนละช่วงเวลา และวัดบนเครื่อง Apple M4 16 GB (บางส่วน) ต้องระบุว่าเวลาไม่รับประกันบนเครื่องอื่น
6. ถ้าผลต่ำกว่าเป้า **ให้รายงานตรงๆ** และอธิบายสาเหตุ นี่เป็นข้อได้เปรียบ ไม่ใช่ข้อเสีย
7. ทุกตัวเลขในสไลด์ให้ใส่ที่มา (ชื่อไฟล์ report) ใน footnote เล็กๆ
8. **ห้ามเติมหัวข้อให้ดูเต็ม** — ถ้าไม่มีข้อมูลจริงรองรับ ให้ตัดทิ้ง ดีกว่าใส่ข้อความที่ไม่ได้มาจากโปรเจกต์ (เช่น อย่าอ้างโมเดลหรือเทคนิคที่โค้ดไม่ได้ใช้)

## 4. ภาพรวมระบบ

```
ผู้ใช้ → Web (Next.js) → proxy → API (FastAPI) → OCR pipeline (model/extract.py)
                                        │                   ↓
                                        │          JSON + validation
                                        ↓
                                  SQLite (บันทึก/ค้นหา)
```

- **Frontend:** Next.js 16 + React + Tailwind CSS 4 — อัปโหลดไฟล์ (หลายไฟล์พร้อมกัน, ลากวาง, ถ่ายรูปด้วยกล้อง), ตรวจและแก้ไขผลในช่องกรอก (แก้ได้ทุกช่อง เป็นสีเหลืองเมื่อระบบสงสัย ตรวจซ้ำอัตโนมัติ), บันทึก, ค้นหา (รายชื่อนักศึกษาทั้งหมด คลิกดูผลรายวิชารายภาค ค้นตามรหัสวิชา)
- **Backend:** FastAPI + Uvicorn + Pydantic — `/api/transcripts/extract`, `/api/validate`, `/api/documents`, `/api/students`, `/api/grades`, `/api/suggest`, `/api/health`
- **ฐานข้อมูล:** SQLite 4 ตาราง: `students`, `documents`, `semesters`, `course_results`
- **รัน:** Docker Compose (web + backend) — `docker compose up --build` แล้วเปิด `http://localhost:3000`
- **อินพุตที่รองรับ:** PDF, PNG, JPG/JPEG, TIFF, HEIC/HEIF ไม่เกิน 20 MB ต่อไฟล์
- **รูปแบบเอกสาร 4 แบบ:** ปริญญาตรี ไทย / ปริญญาตรี อังกฤษ / บัณฑิตศึกษา ไทย / บัณฑิตศึกษา อังกฤษ (ตรวจอัตโนมัติ หรือเลือกเอง)
- **ผลลัพธ์:** JSON ตาม schema `header_detail` (ข้อมูลนักศึกษา) / `transcript_detail` (ภาคการศึกษา → รายวิชา, GPA, หน่วยกิต) / `footer_detail`

## 5. Pipeline (ใช้วาด flowchart) — ขั้นตอนแต่ละขั้น เครื่องมือ และพารามิเตอร์

เส้นทางแตกตามชนิดไฟล์ ให้วาดเป็น flowchart ที่มีจุดตัดสินใจ (diamond) ชัดเจน

> ⚠️ ตารางนี้คือ **ข้อมูลต้นทาง** ห้ามวางทั้งตารางบนสไลด์หน้าเดียว ให้แยกเป็นหลายสไลด์ตามกลุ่มขั้นตอนในหัวข้อ 8 และเก็บตารางเต็มไว้เป็นสไลด์สำรอง

| # | ขั้นตอน | ทำอะไร | เครื่องมือ/เทคนิค | พารามิเตอร์ที่ยืนยันได้จากโค้ด |
|---|---|---|---|---|
| 0 | รับไฟล์และตรวจ | ตรวจนามสกุล ขนาด และ magic bytes ของไฟล์ | FastAPI, Pydantic | ≤ 20 MB; ภาพ ≤ 30 ล้านพิกเซล |
| 1 | แก้เรขาคณิตภาพ (เฉพาะภาพ) | หาขอบกระดาษแล้วปรับมุมมอง, ตรวจทิศภาพ (หมุนกลับหัว), แก้เอียงเล็กน้อยจากเส้นตาราง | OpenCV (`photo_geometry.py`), EXIF transpose | deskew มุม 0.8–4°; เตือนถ้าหน้ากระดาษเล็กกว่า 900 px (แนะนำ ≥ 1500 px) |
| 2 | อ่านข้อความ — PDF | ดึงข้อความฝังใน PDF ถ้าคุณภาพผ่านเกณฑ์ ไม่ผ่านจึงไป OCR | Poppler `pdftotext -layout` + ตัวตรวจคุณภาพ `text_is_usable` | ข้อความ ≥ 300 ตัวอักษร, อักขระเสียหาย ≤ 2%, ต้องพบคำว่า Transcript และรหัสนักศึกษา |
| 3 | อ่านข้อความ — OCR | เรนเดอร์ PDF/ภาพเป็นภาพแล้วทำ OCR | Poppler `pdftoppm`, Tesseract (ภาษา `eng`, สำรอง `tha+eng`), Pillow | เรนเดอร์ 250 DPI; `--psm 6`; ภาพกว้าง < 2000 px ขยาย 2× (LANCZOS) |
| 4 | ตรวจรูปแบบเอกสาร | ตัดสินว่าเป็น 1 ใน 4 รูปแบบ | `detect_format` + `formats.json` | ผู้ใช้เลือกเองได้ (override) |
| 5 | อ่านตามโครงสร้างตาราง | PDF ปริญญาตรีอ่านคอลัมน์ซ้ายจนจบก่อนขวา; ภาพ: เลือก preprocessing/PSM ตามรูปแบบ, หาตำแหน่งคอลัมน์จากกรอบรหัสวิชา, OCR แยกช่อง (cell OCR) เฉพาะแถวที่อ่านไม่ผ่าน (กรอง confidence) | Tesseract, `layout_ocr.py`, `cell_ocr.py` | ปริญญาตรีไทย original/PSM4; ปริญญาตรีอังกฤษ sharpen/PSM6; บัณฑิตไทย sharpen/PSM4; บัณฑิตอังกฤษ autocontrast/PSM4 (เลือกจาก tuning 144 runs บน dev); โหมดเลย์เอาต์ `auto` เลือก profile หรือ detected ด้วยคะแนนโครงสร้าง |
| 6 | ภาพถ่ายมือถือ/หน้าจอ | อ่านตารางภาพถ่ายความละเอียดสูงด้วย recognizer ที่ฝึกเพิ่ม | Tesseract LSTM fine-tune (`eng_phone`), `phone_table.py`, `screen_table.py`, SIFT+RANSAC (เตรียมข้อมูลฝึก) | ฝึก 300 iterations, learning rate 0.0001; ชดเชยเอียงตาราง shear ±0.03; ใช้เมื่อภาพกว้าง ≥ 1800 px |
| 7 | Parse เป็น JSON | แยกหัวเอกสาร ภาคการศึกษา รายวิชา สรุป และท้ายกระดาษ ด้วยกฎ regex | Python (`parse_*` ใน `extract.py`) | deterministic ไม่ใช้ LLM; ไม่ใช้ชื่อไฟล์หรือ ground truth ตอน inference |
| 8 | Post-process | ซ่อมข้อความ OCR: รหัสวิชาและหัวข้อจาก catalog (exact + fuzzy ที่มี threshold/margin), ซ่อมตัวอักษรไทยที่สับสนเฉพาะตำแหน่ง, กู้หัวภาคที่ OCR เพี้ยน, กู้ GPA สะสมจากหลายรอบ OCR | `course_catalog.py` | catalog สร้างจาก dev 35 ฉบับเท่านั้น (ไม่ใช้ test); GPA รับเฉพาะ 0.00–4.00; ไม่เดาค่าที่อ่านไม่ได้ ให้เป็น `null` |
| 9 | Validation | ตรวจโครงสร้างและช่วงค่า ส่ง error/warning พร้อมตำแหน่งฟิลด์ | `validate.py` | รหัสนักศึกษา 8 หลัก; รหัสวิชา 8 หลัก; หน่วยกิต 0–30; เกรดอยู่ในรายการที่รองรับ; GPA 0–4; ภาค 0–3; ปี 2400–2700 |
| 10 | ตรวจ-แก้ โดยผู้ใช้ | ผู้ใช้เห็นช่องที่ระบบสงสัยและแก้ตรงๆ ระบบตรวจซ้ำ | Next.js, `/api/validate` | — |
| 11 | บันทึกและค้นหา | บันทึกลง SQLite, ค้นตามรหัสนักศึกษา/ชื่อ/รหัสวิชา | SQLite | รายชื่อแสดงสูงสุด 500 คน |

**ข้อสังเกตสำหรับ flowchart:** ใส่จุดตัดสินใจเหล่านี้
- ไฟล์เป็น PDF หรือภาพ?
- PDF มี text layer ที่ผ่านเกณฑ์คุณภาพไหม? (ใช่ → ข้ามไป parse; ไม่ → OCR)
- ภาพเป็นภาพถ่ายความละเอียดสูงหรือไม่? (ใช่ → phone recognizer)
- คะแนนโครงสร้างต่ำ → ลองเลย์เอาต์แบบ detected
- Validation พบปัญหา → ขึ้นสถานะ "ควรตรวจสอบ" ให้ผู้ใช้แก้

ควรมี flowchart อย่างน้อย 2 แผ่น: (ก) ภาพรวมระบบแบบ end-to-end (ข) pipeline ภายในการสกัดข้อมูล (ตาราง 0–9 ข้างบน) โดยกำกับเวลาที่วัดได้ของแต่ละเส้นทาง

Local VLM (Typhoon-OCR 1.5 3B → Qwen3 4B ผ่าน Ollama, ภาพ 150 DPI, 4 ฉบับสมดุลกลุ่มรูปแบบ): สำเร็จ 1 จาก 4 ฉบับ ฉบับที่สำเร็จถูก 1/75 ฟิลด์ (1.33%) ใช้ 121.1 วินาที อีก 3 ฉบับ timeout (120 วินาที) → **ไม่เลือกเป็นเส้นทางหลัก** เพราะแย่กว่าทั้งความแม่นยำและเวลา (ทดสอบบนเครื่องที่ใช้พัฒนาเท่านั้น)

เหตุผลอื่นที่ควรเล่า:
- PDF บางไฟล์มี text layer แต่ได้อักขระเพี้ยน จึงต้องมีตัวตรวจคุณภาพก่อนใช้
- รวมโมเดลใหม่แบบ "แทนทุกแถว" ทำให้คะแนนลด (64.43% → 63.80%) จึงเก็บแบบ confidence-gated เฉพาะแถวที่ parse ไม่ได้ (เพิ่มเป็น 66.35%)
- ไม่เดาค่าที่อ่านไม่ได้ (ให้ `null` + แจ้งเตือน) เพื่อไม่ให้ข้อมูลผิดถูกบันทึกเงียบๆ

## 7. ผลการทดสอบ (ใช้ได้เฉพาะตัวเลขนี้)

> ⚠️ ตารางในหัวข้อนี้เป็นข้อมูลต้นทางเช่นกัน บนสไลด์หลักให้เลือกตัวเลขเด่นไม่กี่ตัวต่อหน้าเป็นกราฟ/ตัวเลขใหญ่ ตารางเต็มไว้สไลด์สำรอง

**ชุดข้อมูลและการแบ่ง:** transcript จริง 48 ฉบับ (47 ฉบับมี ground truth; 1 ฉบับไม่มี label) แบ่งตามเอกสารต้นทาง: **dev 35 / test 12 / ไม่มี label 1** และได้รับอนุญาตจากอาจารย์ให้ใช้ข้อมูลจริงอย่างเดียว
**Metrics:** Exact field accuracy (ฟิลด์ที่มีค่าใน ground truth ต้องตรงหลัง normalization, ฟิลด์ที่หายนับผิด), row precision/recall/F1 ของแถวรายวิชา, CER, critical-field accuracy (รหัสนักศึกษา รหัสวิชา เกรด GPA), latency เป้าหมายตั้งไว้ exact field > 91% และเวลาเฉลี่ย < 30 วินาที/ฉบับ

## 10. หลักการพรีเซนต์และการออกแบบ (บังคับ)

**หลักการ — สไลด์ต้องถูกหลัก present**
1. **1 สไลด์ = 1 ข้อความหลัก** ห้ามยัดหลายหัวข้อไว้หน้าเดียว (เช่น ห้ามใส่ทั้ง "เครื่องมือ" "พารามิเตอร์" "ผลทดสอบ" รวมกัน)
2. **ชื่อสไลด์เป็นประโยคสรุปใจความ** (เช่น "PDF ที่มี text layer อ่านเสร็จใน 0.4 วินาที" ดีกว่า "ผลการทดสอบ")
3. **ข้อความในหน้าหลัก: ไม่เกิน 3–4 บรรทัด** บรรทัดละไม่เกินราว 12 คำ ตัวเลขสำคัญทำเป็น **ตัวเลขใหญ่** หรือกราฟ
4. **ภาพ/แผนภาพ/กราฟ 1 อย่างต่อหน้า** ใช้ภาพแทนข้อความทุกครั้งที่ทำได้
5. **ตารางในหน้าหลักไม่เกิน 4–5 แถว** ถ้าเกินให้ย้ายไป Backup
6. พารามิเตอร์ที่ต้องโชว์ต่อหน้าไม่เกิน 3–4 ค่า พร้อมเหตุผลสั้นๆ ว่าทำไมเลือกค่านั้น
7. ลำดับเล่าเรื่องต่อเนื่อง: ปัญหา → วิธี → ผล → ข้อจำกัด และทุกหน้า Core ต้องเล่าจบได้ใน 40–60 วินาที
8. ทุกกราฟต้องมีแกนและหน่วยชัดเจน และใส่ที่มาของตัวเลขเป็น footnote เล็กๆ (ชื่อ report)
9. ให้ไฟล์ PDF อ่านเองได้: นอกจากชื่อสไลด์ ให้มี **คำอธิบายสั้น 1 บรรทัดใต้ภาพ/กราฟ** บอกว่าควรอ่านอะไรจากภาพนั้น

- ส่งออกเป็น **PDF** ตรวจว่าภาษาไทยไม่แตก (สระ/วรรณยุกต์) และภาพไม่เบลอ

## 11. สิ่งที่ต้องส่งมอบกลับมา

1. **แผนสไลด์ทีละหน้า** ตามหัวข้อ 8: ชื่อสไลด์ (ประโยคสรุป), ข้อความบนสไลด์ (ไม่เกิน 3–4 บรรทัด), ภาพ/กราฟที่ใช้พร้อมข้อมูลกราฟ, footnote ที่มา, ระบุว่า Core หรือ Backup และเวลาที่ควรใช้ต่อหน้า
