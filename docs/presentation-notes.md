## 1. Application และสมาชิก

### เนื้อหาที่ต้องบอก

- ชื่อกลุ่ม: loso
- กวีวัฒน์ สานนท์กุลวัฒน์ — 67070005
- ภคพล โพธิวร — 67070124
- ภัทรพล เพ็ชรรัตน์ — 67070127
- Application: OCR Transcript แปลงใบแสดงผลการศึกษาแบบ PDF หรือรูปภาพเป็นข้อมูลนักศึกษา ภาคเรียน รายวิชา เกรด และ GPA
- ผู้ใช้ตรวจแก้ก่อนบันทึก และค้นหาข้อมูลนักศึกษาหรือรายวิชาผ่านเว็บได้

### ตัวอย่างคำพูด

> กลุ่มของเราชื่อ loso สมาชิกคือ กวีวัฒน์ สานนท์กุลวัฒน์ รหัส 67070005 ภคพล โพธิวร รหัส 67070124 และภัทรพล เพ็ชรรัตน์ รหัส 67070127 เราพัฒนา OCR Transcript เพื่อแปลงใบแสดงผลการศึกษาแบบ PDF หรือรูปภาพเป็นข้อมูลนักศึกษา รายวิชา เกรด และ GPA ผู้ใช้ตรวจแก้ผลก่อนบันทึก แล้วค้นหาข้อมูลนักศึกษาหรือรายวิชาได้ผ่านเว็บครับ

## 2. Process — ระบบทำงานตามลำดับอย่างไร

1. เปิด Docker Desktop และรัน Docker Compose เพื่อเริ่ม Backend และ Web
2. ผู้ใช้อัปโหลดเอกสารผ่าน Next.js
3. FastAPI ตรวจชนิดไฟล์และขนาด
4. ถ้าเป็น PDF ที่มีข้อความผ่านเกณฑ์ และไม่ได้บังคับ OCR จะดึงข้อความด้วย pdftotext
5. ถ้าเป็น PDF สแกนหรือรูปภาพ จะเตรียมภาพและอ่านด้วย OCR; ภาพถ่ายมีการตรวจทิศทางและขอบกระดาษตามเงื่อนไข
6. ตรวจภาษาและรูปแบบเอกสาร แล้วแยกข้อมูลเป็น JSON
7. ตรวจความถูกต้องและแสดงคำเตือนให้ผู้ใช้ตรวจแก้
8. ผู้ใช้กดบันทึกผลที่ตรวจแล้วลง SQLite และค้นหาข้อมูลผ่านเว็บ

| เครื่องมือ | หน้าที่ |
|---|---|
| Docker Compose | เริ่มบริการของระบบ |
| Next.js | หน้าอัปโหลด ตรวจแก้ และค้นหา |
| FastAPI | รับไฟล์ เรียก OCR ตรวจข้อมูล บันทึก และค้นหา |
| Poppler: pdftotext | ดึงข้อความจาก PDF |
| Poppler: pdftoppm | แปลง PDF เป็นภาพสำหรับ OCR |
| Pillow / OpenCV / NumPy | เปิดภาพ เตรียมภาพ และปรับ geometry |
| pillow-heif | ช่วยให้ Pillow เปิด HEIC/HEIF |
| SQLite | เก็บเอกสาร ภาคเรียน และรายวิชา |

### ตัวอย่างคำพูด

> ผู้ใช้อัปโหลดเอกสารผ่านหน้าเว็บ Next.js จากนั้น FastAPI ตรวจชนิดและขนาดไฟล์ ถ้าเป็น PDF ที่มีข้อความอ่านได้ ระบบจะดึงข้อความโดยตรง แต่ถ้าเป็น PDF สแกนหรือรูปภาพ จะเตรียมภาพและอ่านด้วย OCR เมื่อได้ข้อความแล้ว ระบบตรวจภาษาและรูปแบบเอกสาร แยกข้อมูลเป็น JSON และตรวจความถูกต้อง ก่อนให้ผู้ใช้แก้ไขและบันทึกลง SQLite ครับ

## 3. Model — ใช้โมเดลอะไรและเลือกเพราะอะไร

- ตัวอ่านหลักคือ Tesseract OCR รองรับภาษาไทยและอังกฤษ
- มีตัวอ่าน `eng_phone` ที่ฝึกเพิ่มสำหรับเส้นทางภาพถ่ายมือถือที่เข้าเงื่อนไข
- ใช้เส้นทางผสม PDF text + OCR เพื่อดึงข้อความโดยตรงเมื่อมีคุณภาพเพียงพอ
- ทดลอง Local VLM แล้ว แต่ผลยังไม่ดีและใช้เวลานาน จึงไม่ได้เลือกเป็นวิธีหลัก
- Tesseract อ่านตัวอักษร ส่วนการแยกภาคเรียน วิชา เกรด และ GPA ใช้กฎของโปรแกรมต่อจาก OCR

### ตัวอย่างคำพูด

> ตัวอ่านหลักคือ Tesseract OCR รองรับภาษาไทยและอังกฤษ โดยเราฝึกตัวอ่าน eng_phone เพิ่มสำหรับภาพถ่ายมือถือ เราเลือกเส้นทางผสมระหว่างข้อความใน PDF กับ OCR เพราะ PDF ที่มีข้อความอ่านได้สามารถประมวลผลเร็วและแม่นกว่าอ่านภาพทุกครั้ง ส่วน Local VLM ที่ทดลองใช้เวลานานและผลยังไม่ดี จึงไม่ได้เลือกเป็นวิธีหลักครับ

## 4. Algorithm — ใช้วิธีอะไรแก้ปัญหา

| วิธี | ทำอะไรและช่วยอะไร |
|---|---|
| ตรวจคุณภาพข้อความ PDF | ตรวจความยาว อักขระเสีย และคำสำคัญ ก่อนเลือกใช้ข้อความหรือ OCR |
| ปรับทิศทางและขอบกระดาษ | ช่วยจัดภาพกลับหัว ตะแคง และถ่ายเอียงให้อยู่ในทิศทางที่อ่านได้เมื่อมีหลักฐานเพียงพอ |
| แบ่งพื้นที่เอกสาร | อ่านหัวเอกสาร ตาราง และคอลัมน์แยกกัน ลดชื่อวิชาปนกับเกรด |
| ตรวจภาษาและรูปแบบ | เลือกวิธีอ่านสำหรับไทย/อังกฤษ และปริญญาตรี/บัณฑิตศึกษา |
| Parser และ Regex | แยกข้อความเป็นข้อมูลนักศึกษา ภาคเรียน รายวิชา เกรด และ GPA |
| Post-processing และ catalog | ใช้กฎและพจนานุกรมจาก dev ช่วยซ่อมข้อความ OCR บางกรณี |
| Validation | ตรวจรหัส 8 หลัก เกรดที่รองรับ และ GPA ช่วง 0–4 พร้อมแจ้งจุดที่ต้องตรวจทาน |
| เลือกผลหลัง deskew | รับผลใหม่เมื่อโครงสร้างข้อมูลดีขึ้นตามเกณฑ์ โดยไม่ให้จำนวนวิชาหรือข้อมูลสำคัญลดลง |

### ตัวอย่างคำพูด

> เราเลือกวิธีอ่านตามรูปแบบเอกสาร แบ่งพื้นที่ตาราง และใช้กฎแยกข้อมูล สำหรับภาพที่เอียงเล็กน้อย ระบบอาจอ่านภาพหลังปรับมุมซ้ำ แล้วเลือกผลใหม่เมื่อข้อมูลมีโครงสร้างดีขึ้น เพื่อป้องกันการปรับภาพแล้วอ่านแย่ลง แต่ภาพเบลอหรือมืดยังมีข้อจำกัดครับ

## 5. Parameters — ตั้งค่าอะไรไว้บ้าง

| ค่า | ที่ใช้ในระบบหรือการทดลอง |
|---|---|
| ขนาดไฟล์อัปโหลด | ไม่เกิน 20 MB |
| เกณฑ์ข้อความ PDF | อย่างน้อย 300 ตัวอักษร, อักขระเสียไม่เกิน 2%, พบคำสำคัญของ Transcript และรหัสนักศึกษา |
| ความละเอียด PDF สำหรับ OCR | 250 DPI |
| การขยายภาพใน OCR รอบแรก | 2× เมื่อภาพกว้างน้อยกว่า 2,000 px |
| ภาษา OCR รอบแรก | `eng` และสำรองด้วย `tha+eng` ตามข้อความที่พบ |
| PSM ตาม profile | ปริญญาตรีไทย 4, ปริญญาตรีอังกฤษ 6, บัณฑิตไทยและอังกฤษ 4 |
| การเตรียมภาพตาม profile | ไทยปริญญาตรี: original; อังกฤษปริญญาตรีและไทยบัณฑิต: sharpen; อังกฤษบัณฑิต: autocontrast |
| การฝึก eng_phone ที่เลือก | 300 iterations, learning rate 0.0001 |

ค่าของ OCR ต่างกันตามเส้นทางและพื้นที่ที่อ่าน ตารางนี้เป็นค่าหลัก ไม่ได้หมายความว่าทุก OCR pass ใช้ค่าเดียวกัน

### ตัวอย่างคำพูด

> ค่าพารามิเตอร์เลือกจากการทดลองบนชุดพัฒนา เช่น PSM 4 และ 6 ให้ผลต่างกันตามรูปแบบเอกสาร ส่วนตัวอ่านภาพมือถือทดลองหลายค่าการฝึก แล้วเลือก 300 iterations กับ learning rate 0.0001 ซึ่งได้ CER บน validation 2.31% อย่างไรก็ตาม ยังเป็นเอกสารชุดเดียวกับที่ใช้ฝึก จึงต้องทดสอบเอกสารใหม่เพิ่มเติมครับ

## 6. ผลทดสอบและเวลารัน — สรุปท้ายการนำเสนอ

ตัวเลขต่อไปนี้อ้างอิงชุดรายงานที่ใช้ในสไลด์ ไม่ใช่ผล benchmark ใหม่ ณ วันที่จัดทำบันทึก

| ชุดอินพุต | Exact field accuracy | เวลาเฉลี่ยต่อเอกสาร |
|---|---:|---:|
| PDF test ครั้งแรก | 88.34% | ดูรายงานของชุดนั้น |
| PDF test หลังปรับระบบ | 97.68% | ดูรายงานของชุดนั้น |
| ภาพต้นฉบับ test 12 ฉบับ | 95.74% | 9.42 วินาที |
| ภาพ augmented 60 ภาพ | 69.74% | 14.22 วินาที; สูงสุด 44.33 วินาที |
| ภาพมือถือ HEIC 6 ภาพ | 97.29% | 27.54 วินาที |
| ภาพถ่ายหน้าจอ 4 มุม | 70.50% | 30.90 วินาที |

- Exact field accuracy: จำนวนฟิลด์ที่ตรงเฉลยหารด้วยฟิลด์ทั้งหมด; ฟิลด์ที่หายนับว่าผิด
- Row F1: วัดการจับแถวรายวิชา ทั้งแถวที่ถูกต้อง หาย และเกิน
- CER: อัตราความผิดพลาดระดับตัวอักษร ยิ่งต่ำยิ่งดี; ใช้ประเมินการฝึก OCR
- เวลาเฉลี่ยรวมเป็นคนละค่ากับเวลารายขั้น และไม่รวมเวลาที่ผู้ใช้นั่งตรวจแก้
- PDF test หลังปรับระบบเป็น reused test; ผลภาพมือถือยังเป็นเอกสารชุดเดียวกับที่ใช้ฝึก ส่วน augmented เป็น dev จึงไม่ควรอ้างว่าเป็นความแม่นยำกับเอกสารใหม่ทั้งหมด

### ตัวอย่างคำพูด

> ผลทดสอบแสดงว่าระบบอ่าน PDF และภาพชัดได้ดี แต่ภาพเบลอ มืด และมุมเอียงยังเป็นข้อจำกัด ด้านความเร็ว ภาพต้นฉบับใช้เฉลี่ย 9.42 วินาที ส่วนภาพ augmented ใช้ 14.22 วินาที แม้เฉลี่ยต่ำกว่า 30 วินาที แต่บางภาพใช้ถึง 44.33 วินาที อีกทั้งชุดทดสอบบางส่วนเคยใช้ปรับระบบแล้ว จึงต้องเก็บเอกสารใหม่เพื่อทดสอบเพิ่มเติมครับ
