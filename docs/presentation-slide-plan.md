# แผนสไลด์ OCR Transcript — กลุ่ม loso

ไฟล์ใหม่สำหรับนำเนื้อหาไปจัด PowerPoint ทีละหน้า โดยไม่กำหนดเวลาพรีเซนต์

ลำดับการเล่า: แอปทำอะไร → ระบบทำงานอย่างไร → วิธีอ่านเอกสารและค่าที่เลือก → วิธีวัดผล → ผลและข้อจำกัด → เวลารันรายขั้น → สิ่งที่ต้องพัฒนาต่อ

มี 25 หน้าหลัก และ 6 หน้าสำรอง. ทุกหัวข้อที่อาจารย์กำหนดอยู่ในหน้าหลัก หน้าสำรองเก็บรายละเอียดเพิ่มเติมสำหรับตอบคำถาม

## วิธีใช้แผนนี้

- “ข้อความบนสไลด์” คือข้อความที่ให้ผู้ชมอ่าน ส่วน “ประเด็นพูด” อยู่ใน speaker notes ไม่ต้องวางทั้งหมดบนหน้า
- แต่ละหน้ามีข้อสรุปหลักหนึ่งประเด็น ถ้ารูปเต็มพื้นที่แล้วให้เหลือข้อความเพียงประโยคสรุป
- ใช้รูปเดิมจาก `docs/presentation/slide_assets/` และ `charts/` ซึ่งตรวจดูแล้ว. รูปที่ไม่มีให้สร้างเป็นแผนภาพหรือตารางแก้ไขได้ใน PowerPoint ตามที่ระบุ
- ภาพหน้าจอควรขยายเฉพาะส่วนที่กำลังอธิบาย โดยรักษาข้อความที่เป็นหลักฐานให้อ่านได้
- แหล่งตัวเลขใส่เป็น footnote ขนาดอ่านได้; ข้อจำกัดที่มีผลต่อการตีความ เช่น reused test ต้องอยู่ใกล้ตัวเลข ไม่ซ่อนใน footnote
- ตัวเลขเป็นผลรายงานที่ใช้ในสไลด์เดิม ไม่ใช่ benchmark ใหม่. กราฟแต่ละชุดใช้ตัวอย่าง/สภาพการทดลองต่างกัน

## หน้า 5 — ระบบเลือกเส้นทางตามชนิดของเอกสาร

**หัวข้อ:** Process / Flowchart ภาพรวม

**ข้อความบนสไลด์:** PDF ที่มีข้อความอ่านได้ใช้ text layer; PDF สแกนและภาพใช้ OCR

**รูป:** สร้าง Flowchart แบบสั้น:

```text
อัปโหลด → ตรวจไฟล์ → PDF มีข้อความที่ผ่านเกณฑ์หรือไม่?
                        ├─ มี: pdftotext
                        └─ ไม่มี/เป็นภาพ: เตรียมภาพ + Tesseract
ทั้งสองเส้นทาง → แยกข้อมูล → ตรวจผล → ผู้ใช้แก้ไข → บันทึก
```

FastAPI ตรวจชนิด/ขนาดไฟล์ไม่เกิน 20 MB; เส้นทางไม่ผ่านย้อนกลับไปอัปโหลดใหม่. ใส่ชื่อ tools ใต้กล่องที่เกี่ยวข้อง ไม่รวม library ทั้งหมดไว้ในกล่องเดียว

**ประเด็นพูด:** แนะนำภาพรวมก่อนขยาย algorithm แต่ละขั้น. ใช้ข้อความ PDF เมื่อผ่านเกณฑ์และไม่ได้เลือก force OCR

## หน้า 7 — Tesseract อ่านตัวอักษร ส่วน Python แยกข้อมูล

**หัวข้อ:** Model

**ข้อความบนสไลด์**

| ส่วน | หน้าที่ |
|---|---|
| Tesseract ภาษาไทย/อังกฤษ | อ่านภาพเป็นข้อความ |
| eng_phone | ตัวอ่านที่ฝึกเพิ่มสำหรับเส้นทางภาพมือถือที่เข้าเงื่อนไข |
| Python rules / Regex | แยกข้อความเป็นนักศึกษา ภาคเรียน วิชา เกรด และ GPA |

**รูป:** แผนภาพ “ภาพเอกสาร → Tesseract → ข้อความ → Python parser → JSON”. ใส่ตัวอย่างข้อความสั้นหนึ่งบรรทัด

**ประเด็นพูด:** โมเดลอ่านตัวอักษรกับ parser เป็นคนละส่วน. ระบบใช้ Hybrid PDF text/OCR; Local VLM เป็นการทดลองที่ไม่ได้ใช้ในเส้นทางหลัก รายละเอียดอยู่หน้าสำรอง B1

## หน้า 11 — Parser เปลี่ยนข้อความเป็นข้อมูลที่ค้นหาได้

**หัวข้อ:** Algorithm

**ข้อความบนสไลด์:** Regex และกฎแยกข้อมูลตาม label ภาคเรียนและแถวรายวิชา แล้วใช้ post-processing ซ่อมบางกรณี

**ประเด็นพูด:** รักษาวิชาแยกตามภาค ไม่รวมรหัส/ชื่อ/เกรดข้ามแถว. catalog ช่วยซ่อมข้อความบางส่วน แต่ไม่ใช่หลักฐานว่าอ่านเอกสารใหม่ได้ถูกทั้งหมด รายละเอียดการทดสอบ catalog อยู่ B3

## หน้า 13 — การฝึกภาพมือถือแบ่งตามมุมของสองเอกสาร

**หัวข้อ:** Model / ข้อมูลฝึก

**ข้อความบนสไลด์**

HEIC 6 ภาพ = 2 เอกสาร × 3 มุม

| มุม | ใช้ทำอะไร |
|---|---|
| มุม 1 | Train |
| มุม 2 | Validation และเลือกค่าฝึก |
| มุม 3 | Final angle test |

ข้อความเด่นด้านล่าง: เป็นเอกสารสองฉบับเดิม จึงยังไม่ใช่ independent document holdout

**รูป:** แผนภาพสองเอกสาร แต่ละฉบับมีสามมุม ใช้สีแสดง train/validation/test

**ประเด็นพูด:** แยกมุมเพื่อวัดการอ่านมุมที่กันไว้ แต่เนื้อหาเอกสารยังเหมือนเดิม. อย่าเรียกว่า unseen document test

## หน้า 14 — เลือกค่าฝึกจาก CER บน validation

**หัวข้อ:** Model / Parameters

**ข้อความบนสไลด์**

| Iterations | Learning rate | Validation CER |
|---:|---:|---:|
| 100 | 0.0001 | 6.17% |
| **300** | **0.0001** | **2.31%** |
| 600 | 0.0001 | 2.49% |
| 300 | 0.0003 | 2.31% |

**รูป:** ตารางนี้เป็นองค์ประกอบหลัก; ไม่ต้องวางกราฟ CER ซ้ำในหน้าเดียวกัน

**ประเด็นพูด:** เลือก 300 iterations และ learning rate 0.0001. เพิ่ม iterations ไม่ได้ทำให้ดีขึ้นเสมอ. CER คือความผิดระดับตัวอักษร; วัดบน validation 109 บรรทัดของเอกสารเดิม

**รูป:** ตารางสี่แถว. ตัวอย่าง “861/885 ฟิลด์ = 97.29%” ใช้เป็นคำอธิบายขนาดเล็กใต้แถว Exact field

**ประเด็นพูด:** แถวครบไม่ได้แปลว่าชื่อวิชาและเกรดทุกช่องถูก. CER 2.31% ไม่ใช่ค่าเดียวกับ Exact field accuracy. เป้าหมายในสไลด์คือ accuracy >91% และ latency เฉลี่ย <30 วินาที

## หน้า 23 — เวลาแยกขั้นของ PDF fallback OCR

## หน้า 24 — เวลาแยกขั้นของภาพ PNG

**ประเด็นพูด:** เฉลี่ยจาก 16 runs ของ PNG 150 DPI. เวลาใน logic ไม่รวม Tesseract ที่นับแยกแล้ว. รายละเอียด parser 0.00323, post-processing 0.00203, validation 0.00014 วินาที. การเปิดระบบ/upload/save/search ยังไม่มีเวลาวัดรายขั้นในรายงานนี้ ต้องจับเพิ่มหากจะอ้างครบตั้งแต่เปิดเครื่องถึงค้นหา
